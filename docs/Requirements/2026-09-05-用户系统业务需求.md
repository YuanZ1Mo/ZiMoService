## 2. 全局约定

### 2.1 会话与鉴权

* 会话:Cookie `zm_session`(服务端存哈希,多会话并发模型,每账号上限 5 个 LRU 踢旧;30 天滑动 + 90 天绝对双上限)
* 鉴权:所有业务接口请求须携带有效会话;会话无效返回 401,前端统一跳登录

### 2.2 心跳

* 门户页维持心跳(10s 一次),用于感知:会话失效(401 立即下线)、服务端策略/变更推送、连接中断(提示但不强制下线,恢复后自动续)

### 2.3 模块索引规则

* 正数索引从 1 开始,**越小越靠前**(1、2、3 …)
* 负数索引从 -1 开始,**永远排在正常(正数)索引之后,数值越大越靠前**(-1、-2、-3 …)
* 全序:正数升序在前,负数区(-1 最先、依次递减)在后
* 本期:用户主页 = 1,系统管理 = -1

### 2.4 页面端口与 API 端口

* 页面端口(80/443)承载页面与静态资源;业务 API 走 RESTful 端口(39441 `/zimo/api`)
* 跨端口同站,Cookie 需同站点传输(credentials include)
* 业务 API 面校验请求 `Origin`(仅本站点回显),与 `SameSite=Lax` 配合防跨站请求伪造(CSRF)

### 2.5 页面风格与视觉设计

**基调:青春、活泼、明亮**

* 主色调:明快的高饱和年轻化配色(活力蓝/青/粉等),辅以柔和中性色保证可读性;不做暗沉厚重风格
* 布局:大面积留白 + 圆角卡片化信息层级 + 柔和阴影;扁平为主,可带轻微渐变点缀

**灵动特效(硬约束:低 CPU 开销)**

* 特效以"轻量点缀"为原则:状态徽标脉冲、渐变流动、悬停弹性/磁吸反馈、页面切换淡入过渡、加载骨架屏
* **性能约束**:
  * 动画只使用 `transform` / `opacity`(GPU 合成),避免触发布局/重绘密集操作
  * 动画时长短、低频次;禁止常驻高频动画、禁止高 CPU 的实时 Canvas 渲染(除用户显式触发,如用户主页特效区)
  * 适配 `prefers-reduced-motion`:用户偏好减少动效时自动降级为静态呈现
* 特效范围与具体形态(如粒子/流光)在设计阶段细化,本期保证"可见但不打扰"

**交互范式(以当前主流 Web 应用为模板)**

* 卡片化内容区、骨架屏加载、Toast 轻提示、模态确认、抽屉/滑出面板、下拉菜单
* 响应式:桌面端悬浮导航 + 移动端抽屉式导航;模块内容区随抽屉收起自适应
* 空状态引导、错误状态可视化(字段级内联报错)
* 亮/暗主题适配(跟随系统偏好;可选手动切换)

### 2.6 页面组织(SPA)

> 技术形态(已确认):前端为**单页应用**(Vite + Vue 3 构建,产物为单一 `index.html` + 静态资源,由服务端托管),页面路由全部在前端(`vue-router`)处理;服务端对页面路径统一 SPA 回落 + 鉴权门禁。本节替代原"物理 html 文件"组织方式,路径语义不变。

* **通用页面**(无需会话的独立页面:登录 / 注册 / 找回密码 / 强制重置 / 404 等)→ 前端路由 + 页面组件,路径不变:`/login` `/register` `/reset` `/force-reset` `/404`
* **门户模块页面**(模块内的页面,如用户主页、系统管理-用户管理)→ 前端路由 + 模块组件,**每个模块一个路由(懒加载)**,门户壳以 keep-alive 嵌入渲染,模块切走保留运行状态
* **页面命名映射**:模块 `code` 转小写 kebab-case 作为路由与组件名(`home` → `/portal/home`、`userManager` → `/portal/user-manager`),由服务端下发的模块清单 `{code,name,url,index}` 驱动
* 具体工程目录与机制见设计文档《2026-09-05-用户系统模块设计.md》§8

### 2.7 性能指标(基线)

> 第一期验收与性能回归以此为据;口径:单机部署(单服务进程 + 本地 SQLite + 同机 Redis),延迟为 P95,吞吐为持续值;未达标时优先优化访问策略而非放宽指标。

| 指标 | 基线 | 说明 |
| --- | --- | --- |
| 注册/登录接口 P95 | ≤ 500ms | 含 PBKDF2-HMAC-SHA256(600k 迭代)哈希耗时;哈希必须走工作池,事件循环不阻塞 |
| 登录接口峰值 | ≥ 50 QPS | 受哈希 CPU 并行度约束;限流窗口(60s/20 次)为单键值维度,不冲突 |
| 心跳接口 | ≥ 200 QPS 持续 | 10s 心跳对应 ≥ 2000 在线会话;**心跳触达只读,续期写库按节流策略**(见模块设计 §3.4) |
| 在线会话容量 | ≥ 2000 | 受心跳 QPS 与 LRU 上限(每账号 5)共同约束 |
| 会话校验 AuthAndTouch P95 | ≤ 50ms | 走 Redis/内存判定,不逐次查库 |
| 用户管理列表(分页/搜索) P95 | ≤ 200ms | 万级用户规模 |
| 管理操作(停用/删除/重置/改角色) P95 | ≤ 300ms | 含事务、审计与安全事件落库 |
| 密码哈希单次耗时 | 50~200ms | 作为延迟预算基准,不单独作为验收指标 |

## 3. 全局路由与访问控制

### 3.1 免鉴权路径白名单

以下路径**不需要会话**即可访问:

| 路径 | 说明 |
| --- | --- |
| `/login` | 登录页 |
| `/register` | 注册页 |
| `/reset` | 找回密码页(本期页面预留,不可用) |
| `/404` | 自定义 404 页 |
| 静态资源 | `/css/*`、`/js/*`、`/resource/*` 等(登录页/注册页渲染所必需) |

> 门户模块页面(`/modules/*`)**不在白名单**,按业务页面鉴权:页面模板本身不含数据,数据一律经鉴权 API 获取;未登录访问按 3.2 处理。

### 3.2 鉴权拦截规则

* 除白名单外,**访问前端服务器的任意链接必须先鉴权**
* 鉴权未通过 → 302 跳转 `/login`(可带 redirect 回跳参数)
* 鉴权通过 → 按路径规则继续(见 3.3)

### 3.3 路径跳转规则

| 请求路径 | 鉴权成功 | 鉴权失败 |
| --- | --- | --- |
| `/`(服务器根) | 跳转 `/portal`(门户) | 跳转 `/login` |
| `/portal` 及 `/portal/*` | 渲染门户 | 跳转 `/login` |
| 其他业务页面 | 渲染对应页 | 跳转 `/login` |
| 白名单页面(`/login` 等) | 已登录访问 `/login` → 直接跳 `/portal`(不回显表单) | 正常渲染 |

### 3.4 401 统一处理

* 门户内任一接口返回 401 → 记录回跳地址 → 跳登录页(登录成功后回跳)

## 4. 注册

### 4.1 页面入口与跳转

* 登录页提供"注册账号"按钮 → 跳 `/register`
* 注册页提供"返回登录"按钮 → 跳 `/login`
* **注册成功 → 直接跳转门户**(自动登录,无需再走登录页)

### 4.2 三种注册方式(本期仅账号注册)

| 方式 | 入口状态 | 表单字段 | 说明 |
| --- | --- | --- | --- |
| 账号注册 | ✅ 本期实现 | 账号、密码、昵称(选填) | 账号规则见 4.3 |
| 手机注册 | 预留(UI 可见,不可用) | 手机号、验证码(+发送验证码按钮)、昵称 | 验证码下发本期不实现 |
| 邮箱注册 | 预留(UI 可见,不可用) | 邮箱地址、验证码(+发送验证码按钮)、昵称 | 验证码下发本期不实现 |

### 4.3 账号注册字段规则

| 字段 | 规则 | 校验失败报错示例 |
| --- | --- | --- |
| 账号 | 4-30 位 `[a-z0-9_-]`;首尾不能是 `_`/`-`;统一小写;唯一 | "账号已存在" |
| 密码 | 8-64 位;不含空格/控制字符;强度评分须达标(zxcvbn ≥ 2) | "密码强度过低" |
| 昵称 | 1-20 码点;不含空白;选填,默认与账号一致 | "昵称不能包含空白字符" |

### 4.4 错误提示

* 字段级错误:对应输入框下方展示
* 服务端错误(账号占用、限流等):按错误码映射到字段或表单顶部
* 网络错误:表单顶部兜底提示

### 4.5 注册角色分配

* **首个注册用户 → `developer` 权限**(开发者,level 3);判断依据:注册时系统中不存在任何有效用户
* **后续注册用户 → `user` 权限**(普通用户,level 1)
* **`admin` 权限**(管理员,level 2)不通过注册获得,由具备资格的管理员在用户管理中通过提权操作授予

| --- | --- | --- | --- |
| 账号登录 | ✅ 本期实现 | 账号、密码 | 账号统一小写 |
| 手机登录 | 预留(UI 可见,不可用) | 手机号、验证码(+发送验证码按钮) | 验证码下发本期不实现 |

### 5.3 错误提示

## 6. 强制重置密码

### 6.1 触发条件

* **用户鉴权结果判定为强制重置密码(`force_change=1`)→ 跳转本页**
* 典型入口:登录成功响应携带 `forceChange=true`(见 5.4);门户内鉴权同样检测该状态,命中即引导到本页

### 6.2 页面行为

* 路径 `/force-reset`(需会话)
* 表单:**仅新密码**(规则同注册:8-64 位、不含空格/控制字符、强度达标)
* 点击"重置":
  * **成功 → 清除 `force_change` → 自动跳转门户**
  * 失败 → 按错误码报错(字段级/表单级),停留本页
* 未处于强制改密状态的会话访问本页 → 直接跳回门户
* **访问边界**:处于强制改密状态(`force_change=1`)的会话,仅允许访问 `/force-reset` 与登出;门户及其他业务页面/接口一律拒绝(响应 403 或引导至本页),完成改密后解除限制

## 7. 门户(壳)

### 7.1 访问控制

* 仅登录后可达(`/portal`);门户中**所有接口请求均须鉴权**,401 → 统一跳登录
* 首页登录成功后跳转入口即 `/portal`

### 7.2 心跳

* 门户保持心跳(10s),见 2.2;401 立即下线,服务端错误 1 次即下线,网络中断提示不强制下线

### 7.3 布局

* **顶部状态栏**:品牌、连接状态、用户菜单(昵称/个人中心)——**固定悬浮,不随页面滚动**;**退出登录按钮**置于状态栏右侧、昵称区域右边
* **侧边导航栏**:功能模块列表,按索引规则排序——**固定悬浮;抽屉式**(可展开/收回;收回时模块内容区自适应新尺寸;移动端为抽屉遮罩模式)
* **工作区**:当前激活模块以**嵌入方式**渲染(不跳新标签页);模块间切换保留各自运行状态(keep-alive)

### 7.4 模块嵌入契约

* 模块 = 服务端按权限下发的模块清单(权限点驱动):code / name / url / index
* 无权限的模块不渲染、不可访问(前端路由 + 服务端接口双重拦截)
* 模块切换不销毁运行状态;支持激活/离开生命周期钩子(如音频模块切走不中断)

### 7.5 登出

* 顶栏"退出登录"→ 调用登出接口(会话作废 + 清除 Cookie)→ 跳转 `/login`;登出为主动行为,不回跳

## 9. 系统管理(模块索引 -1)

### 9.1 结构

* 系统管理内部分**多个子标签**,选择后进入对应管理页
* 本期实现:**用户管理**
* 预留若干 TODO 入口(仅占位展示,点击提示建设中)
* **可见权限**:系统管理模块仅具备 `userManager` 权限点(admin/developer 角色默认拥有)的用户可见、可访问;无权限用户侧边栏不渲染、接口拒绝(403)

### 9.2 用户管理功能

进入用户管理后,以列表/表格展示用户(分页、搜索、角色/状态筛选,数据源自用户主表);页面提供**个人中心**入口(本期仅预留入口,点击提示建设中);登出统一走顶部状态栏右侧按钮(见 7.3)。

对单个用户可执行:

| # | 功能 | 说明 |
| --- | --- | --- |
| 1 | 修改用户主表属性 | **动态获取表属性渲染表单**;特殊属性(`id`、`uid`、`pass_salt`、`pass_hash` 等)置灰不可改;停用、删除等状态可改 |
| 2 | 提权 / 降权 | 修改角色;等级压制:操作者等级必须 > 目标,提升最高到自己的下一级 |
| 3 | 授权模块 / 解除模块权限 | 授予/移除该用户的模块权限(单人覆盖 user_permissions) |
| 4 | 停用该用户 | 停用后不可登录;同时吊销其全部会话 |
| 5 | 删除该用户 | 软删除;不可登录、列表不显示;可恢复 |
| 6 | 强制重置密码 | 生成一次性临时密码 + 置 `force_change=1` + 吊销会话;该用户下次登录走强制改密 |

* 管理操作需记录操作审计(操作者、动作、目标、详情)
* 仅允许操作等级**低于自己**的用户;不可操作自己
* **developer(level 3)为最高等级,无更高等级操作者可对其执行管理操作 → developer 用户不可被删除/停用/重置**,天然自我保护

## 10. 数据库需求(整合 + 增量)

> 表结构细节以《2026-09-05-用户数据库表结构设计.md》为准;本节列出**本业务对数据库的完整依赖与新增项**。

### 10.1 基础表(12 表方案)

| 表 | 本业务角色 |
| --- | --- |
| `users` | 账号/密码/状态/角色/强制改密(核心) |
| `user_profile` | 用户资料(本期头像/偏好可留空) |
| `sessions` | 会话(多会话并发,LRU 上限 5) |
| `password_reset_tokens` | 找回密码令牌(本期未启用,建表预留) |
| `login_locks` | 登录阶梯锁定(uid 可空 + login_key + ip) |
| `rate_limits` | 多维限流(scope×dimension×dim_key) |
| `security_events` | 安全事件(异常登录/越权等落点) |
| `roles` | 角色定义(developer/admin/user)与权限点集合 |
| `permissions` | 权限点定义(门户模块即权限点,含 url/index) |
| `user_permissions` | 单人模块授权/拒绝覆盖 |
| `operation_logs` | 用户管理操作审计 |

### 10.4 权限推导(用户拥有什么模块)
