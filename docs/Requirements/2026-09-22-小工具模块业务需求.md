> 状态:待审阅 · 版本:v1.3 · 日期:2026-09-23
> 范围:门户小工具集(一期:JSON 格式化 + Markdown 编辑器,已实现;二期规划见 §9),纯前端实现
> 关联:用户系统《2026-09-05-用户系统业务需求.md》(会话/鉴权/模块权限/门户契约);SPA 平台约定见《2026-09-05-用户系统模块设计.md》§8;文件中心《2026-09-15-文件空间业务需求.md》(边界:文件中心只管字节,本模块不读写文件空间)

## 1. 背景与目标

### 1.1 背景

平台日常开发与维护中,经常需要临时格式化 JSON、编写 Markdown。现状是去第三方在线工具(内容需粘贴到外部站点,存在隐私外发风险)或本地另开编辑器(平台内无统一入口)。本模块把这类零散小工具收拢到门户内,提供一个统一入口。

定位:**工具逻辑纯前端**。处理的数据不出浏览器、不接触服务器,天然安全;也因此本模块**不产生业务数据接口、不建业务表**——服务端只做两件事:登记一条权限点、提供一个进入页面的鉴权探测接口(见 §2),接入成本最低,新增工具也最快。

### 1.2 业务范围

| 域 | 说明 |
| --- | --- |
| 统一入口 | 门户模块"小工具"(与文件中心、服务器音频同为 `type=0` 门户模块),权限点驱动侧边栏显隐,按 `index=4` 排在服务器音频之后;页面结构参照系统管理(容器页 + 顶部 tab 切换工具) |
| JSON 格式化 | 粘贴/拖入/示例输入;格式化(缩进 2 / 4 / Tab)与压缩(minify);语法校验失败定位到出错行/列并说明原因;结果一键复制 |
| Markdown 编辑器 | 分栏编辑与实时预览(仅编辑 / 仅预览 / 分栏,栏宽可拖);常用工具条与快捷键;草稿自动保存;导入/导出 `.md` 文件;字符统计 |
| 工具现场保留 | 切到其他模块再切回,编辑内容与工具设置不丢失(keep-alive) |

### 1.3 非目标(一期明确不做)

* **JSON**:不做 JSON5 / YAML / TOML / CSV 解析与转换;不做树状浏览、键排序、键折叠、多文档对比
* **Markdown**:不做代码块语法高亮(一期代码块按纯文本展示);不做图片/文件粘贴上传(无服务器,无落点);不做协同编辑与远程保存
* 工具数据不保存到服务器、不写入文件中心、不产生审计记录
* 不做分享、免登录形态;工具不读取服务器上的任何文件
* 不做多语言界面(i18n)

## 2. 全局约定

### 2.1 模块接入姿态

| 项 | 取值 |
| --- | --- |
| 模块名 | 小工具 |
| 权限点 code | `devTools`(门户模块,type=0) |
| 侧边栏入口 | 由权限点 `url` 与 `index` 驱动;`index=4`(排服务器音频之后) |
| 前端页面路由 | `/portal/dev-tools`(kebab 目录名即路由名) |
| 前端模块目录 | `frontend/src/modules/dev-tools/`(容器 `index.vue` + 工具子视图) |
| 前端接口封装 | `frontend/src/api/devTools.js`(`check`,仅一个接口) |
| 服务端模块文件 | `modules/module_dev_tools.{h,cpp}`(权限点登记 + 页面鉴权接口) |
| 接口前缀 | `GET /zimo/api/devTools/check`(页面进入鉴权探测,唯一接口) |
| 默认可见角色 | 仅开发者(`developer`);其余角色由管理员在授权弹窗按需授予 |

### 2.2 会话与鉴权

* 模块进入**必须经服务端鉴权**:唯一接口 `GET …/check` 走标准鉴权链路(会话有效性 + 账号状态 + `devTools` 权限点),通过才允许使用工具
* 三种结果:未登录 401 → 前端统一跳登录页(带回跳);已登录但无权限 403 → 渲染"无权限访问"占位;有权限 200 → 挂载工具
* **"进入"的口径**:首次挂载时判定一次,之后每次从其他模块切回(激活)时复检一次——权限被撤销或账号被停用后,切回即失效并转为"无权限访问"占位(切换会卸载工具,而 JSON 输入不持久化,故此时现场不可恢复,属预期,见 §6)
* 停留在本模块内(不切走、不刷新)期间不做轮询:账号被停用/会话失效由门户壳 10s 心跳兜底(401 立即下线拉回登录页);**仅权限被撤销**时心跳不会卸载已挂载的页面,侧边栏入口随模块清单刷新消失,页面本身在切走再切回时才收敛
* 侧边栏显隐由权限点驱动,页面进入由 check 接口把关,两者双重校验
* 工具功能本身仍纯前端本地处理:**除 check 复检外**不再发起任何请求,工具数据不出浏览器

### 2.3 权限点

权限点经 `ZmPermissionModule::RegisterPermCodeSync` 在装配期登记,默认绑定 `developer` 角色(与 `serverAudioStream` 同姿态):

```
code=devTools,name=小工具,module=portal,url=/portal/dev-tools,type=0,index=4,sort=7,enabled=1,description=门户小工具集(JSON 格式化/Markdown 编辑器)
```

* `module` 仅为权限点分组展示字段(与 `home`/`filehub` 一致取 `portal`),不参与侧边栏过滤与鉴权判定
* `index=4`/`sort=7` 与既有模块构成的全序一致:home 1/1 → filehub 2/4 → serverAudioStream 3/6 → devTools 4/7

## 3. 工具一:JSON 格式化

### 3.1 功能点

| # | 功能 | 说明 |
| --- | --- | --- |
| 1 | 输入 | 文本域直接粘贴;拖入本地文件读取(**不校验扩展名**,按内容解析);点"载入示例"填充内置示例 |
| 2 | 格式化 | 按 2 空格 / 4 空格 / Tab 三种缩进格式化(默认 2 空格) |
| 3 | 压缩 | 去除全部空白与换行,单行紧凑输出 |
| 4 | 校验与定位 | 语法非法时右侧不产出并显示错误条,提示出错行/列与原因。原因优先给中文文案(如"第 3 行第 14 列:意外的逗号"),未命中内置映射时展示浏览器引擎原文(可能为英文);仅在手动触发格式化/压缩时把输入光标定位到出错处,输入态自动重算只提示、不移动光标 |
| 5 | 复制 | 一键复制结果到剪贴板,成功/失败均有轻提示(失败按 §3.2 逐级回退) |
| 6 | 统计 | 页脚展示输入、输出的字符数与行数 |
| 7 | 输出回填 | 输出内容可一键回填到输入,便于二次编辑 |
| 8 | 大文件处理 | 输入超过 **200 万字符**(约 2MB 文本)提示"内容较大,已暂停自动重算,请点格式化 / 压缩",并关闭自动重算(改手动触发),不阻断处理 |

### 3.2 交互细节

* 左右分栏:左侧输入、右侧输出;各自独立滚动;输入变化防抖 300ms 后重算(超过 200 万字符时关闭自动重算,改由按钮触发)
* 校验失败时:右侧**清空并显示错误提示条**(不保留上一次结果,不渲染半成品);光标定位只在手动触发格式化/压缩时执行,输入态自动重算不移动光标、不抢焦点
* 复制走剪贴板 API;被权限拒绝或环境不支持时逐级回退:`document.execCommand('copy')` → 自动选中输出文本并提示"已选中,请手动复制"

## 4. 工具二:Markdown 编辑器

### 4.1 功能点

| # | 功能 | 说明 |
| --- | --- | --- |
| 1 | 分栏 | 仅编辑 / 仅预览 / 编辑+预览 三种模式;分栏时中间分隔条可拖动;模式切换不丢失内容 |
| 2 | 实时预览 | 输入防抖 300ms 渲染;支持 **GFM 常用子集**(§4.2);预览 HTML 经**转义 + 清理**后再插入页面,防 XSS |
| 3 | 工具条 | 标题 H1~H3、加粗、斜体、删除线、行内代码、代码块、引用、无序/有序列表、任务列表、链接、图片、表格、分割线;插入定位到光标处,选中文本时包裹 |
| 4 | 快捷键 | 常用操作绑定快捷键(§4.3);工具条动作多于快捷键,未绑定的动作仍由工具条完成 |
| 5 | 草稿 | 内容自动保存到 localStorage(防抖 1s + 页面卸载前),状态行显示"已保存 HH:MM";提供"清空草稿"按钮(二次确认) |
| 6 | 导入 | 选择本地 `.md` / `.markdown` / `.txt` 文件载入编辑器(替换当前内容,可放弃) |
| 7 | 导出 | 下载为 `.md` 文件,文件名可改(默认 `YYYY-MM-DD-untitled.md`) |
| 8 | 统计 | 字符数、行数、字数在状态行展示;统计口径见 §4.5 |

### 4.2 渲染语法范围(一期)

标题(1~6 级)、加粗、斜体、删除线、行内代码、围栏代码块(语言标记与内容按纯文本展示,不高亮)、引用块、无序/有序列表、任务列表、链接、图片、表格、分割线、转义、段落与硬换行。

**不支持**:HTML 原生标签渲染(源文中写 HTML 一律**转义为文本展示**,不渲染)、脚注、Emoji 简码。

* **换行口径**:只支持硬换行(行尾两个空格或反斜杠);段落内单个换行按 CommonMark 视为软换行(折叠为空格),不生成 `<br>`
* **链接与图片**:链接点击在新标签页打开(不离开门户,不丢现场);图片按源文 URL 直接渲染,请求不携带来源页地址(referrer)

### 4.3 快捷键

| 键 | 动作 |
| --- | --- |
| Ctrl/Cmd + B | 加粗 |
| Ctrl/Cmd + I | 斜体 |
| Ctrl/Cmd + E | 行内代码 |
| Ctrl/Cmd + U | 删除线 |
| Ctrl/Cmd + K | 链接 |
| Ctrl/Cmd + Shift + K | 图片 |
| Ctrl/Cmd + ` | 代码块 |
| Ctrl/Cmd + Alt + 1 / 2 / 3 | H1 / H2 / H3(不用 Ctrl+1/2/3:被浏览器保留为切换标签页,页面拦不住) |
| Ctrl/Cmd + S | 立即保存草稿,提示已保存 |

### 4.4 交互细节

* 滚动跟随:**单向**,仅分栏模式触发;预览滚动按比例映射到编辑区,编辑区滚动**不**反向驱动预览(输入时不被打扰、不互跳)
* 大内容降级:超过约 10 万字符时渲染挪到空闲时段(不阻塞输入);超过约 **26 万字符**时**暂停自动预览**,提示条给出「刷新预览」按钮手动触发一次,回落到阈值以下自动恢复实时预览
* 草稿用**单一固定键**(`zimo-dev-tools:markdown-draft`),多标签页共享同一份、后写覆盖;不做跨页同步(一期)
* 草稿区就地提示"草稿保存在本机浏览器,不区分账号"(§6 跨账号可见风险的知情提示),与"清空草稿"按钮同处
* 导出经浏览器 Blob 下载,不经过服务器
* 内容为空或全空白时,预览区显示空态提示
* 窄屏(宽度 < 768px)下分栏自动降级为单栏,由"编辑 / 预览"切换按钮切换;工具条按钮可键盘 Tab 聚焦并回车触发

### 4.5 统计口径

| 指标 | 口径 |
| --- | --- |
| 字符数 | 正文全部字符(含空白与换行;按 **Unicode 码点**计——代理对算 1,组合 emoji 会拆成多个码点) |
| 行数 | 按换行符切分的段数;空内容为 0 |
| 字数 | 中日韩汉字/假名/谚文每字计 1;连续的拉丁字母与数字串计 1 个词;标点、空白与其他符号不计 |

* JSON 工具页脚只用字符数与行数两列,口径同上

## 5. 页面结构

参照系统管理(system-manager)的容器形态:

```
frontend/src/modules/dev-tools/
  index.vue            # 容器:顶部 tab 切换(JSON 格式化 / Markdown 编辑器),模块进入即保活
  JsonFormat.vue       # 工具一
  MarkdownEditor.vue   # 工具二
```

* 容器页不持业务数据,只做 tab 切换与工具挂载;两个工具视图在容器内以 keep-alive 保活
* tab 名称与顺序:JSON 格式化 → Markdown 编辑器;未来新增工具按序追加(**二期起容器改为分组下拉,见 §9.2**)
* 门户壳(顶栏/侧边栏/特效带)由 PortalLayout 统一提供,模块只渲染内容区

## 6. 数据与存储

除平台既有数据(主题、会话等)外,新增以下 localStorage 键:

| 键 | 用途 | 更新时机 |
| --- | --- | --- |
| `zimo-dev-tools:markdown-draft` | Markdown 草稿正文 | 编辑防抖 1s / 页面卸载前 |

* JSON 输入**不持久化**:切走不丢由 keep-alive 保证,刷新页面不承诺保留(与 §8 验收一致)
* 工具数据与账号、登录状态**无关**:登出不清理,用户间不隔离(开发向工具,本期接受);由此**共用同一浏览器时,后一位使用者可能看到前一位的草稿**——草稿区需就地提示"草稿保存在本机浏览器,不区分账号"(§4.4),并保留"清空草稿"入口
* 不新增 cookie;不写 IndexedDB;不新增服务端存储与表
* 本地数据量通常为 KB 级;Markdown 草稿可随长文增大,受浏览器 localStorage 配额(约 5MB)约束——写入失败(存储被禁用或已满)时必须提示用户,不静默丢弃(见设计 §5.4);无过期策略与清理机制

## 7. 安全与隐私

* 工具处理的数据均在浏览器本地处理与存储;与服务器唯一的交互是进入页面时的 `check` 鉴权探测(不携带任何工具内容)
* Markdown 预览是唯一可执行外部内容路径:源文中的 HTML 标签一律转义为文本展示,渲染管线仍走 marked 解析 + DOMPurify 清理双保险,清理后的 HTML 才进入页面
* 预览中的**远程图片**由源文内容触发,浏览器直连图片地址(不携带 referrer),属用户内容而非本模块引入的资源;源文不写图片则无任何外部请求
* 不引入远程字体/脚本/接口;不采集用户行为数据

## 8. 验收要点(人工验证)

* **权限与鉴权**:developer 登录后侧边栏可见"小工具",两工具可用;普通用户侧边栏不可见,直连页面显示"无权限访问"占位(check 返回 403);浏览器未登录访问 `/portal/dev-tools` 会被服务端页面门禁 302 到登录页——"未登录调用 check 得到 401"只能由 curl 直连 check 或会话中途失效复现
* **权限复检**:有权限用户进入模块后,由管理员撤销其 `devTools` 权限,切到其他模块,再用**地址栏直连 `/portal/dev-tools`**(此时侧边栏入口可能已随模块清单刷新消失)进入,页面应转为"无权限访问"占位;权限未变时切走再切回,工具现场不丢
* **JSON**:合法对象/数组各缩进档位正确;非法输入定位的行/列与原因相符(含一条引擎无内置映射的样例,验证降级为引擎原文),且输入态自动重算不移动光标、手动触发时才定位;压缩→格式化与原文**语义一致**(标准 JSON API 对数字字面会规范化,如 `-0`→`0`、`1e21`→`1e+21`,验收按语义不等价于字节回放);复制成功有反馈;拖入任意文本文件按内容解析;载入示例可用;超过 200 万字符输入提示并暂停自动重算,点格式化/压缩仍能出结果
* **Markdown**:§4.2 语法逐项渲染正确;含 `<script>` 与 `<div>` 的样例源文**均不渲染**、以文本展示;软换行不生成 `<br>`、行尾两空格生成 `<br>`;链接在新标签页打开且门户现场不丢;草稿刷新后恢复;导出后再导入内容一致;§4.3 快捷键逐项生效(未绑快捷键的动作由工具条完成)
* **统计**:按 §4.5 口径抽查(中英混排、emoji、空内容、`\r\n` 行数)
* **大内容降级**:约 26 万字符以上出现"已暂停自动预览"提示,点「刷新预览」可手动出预览;回落到阈值以下自动恢复实时预览;期间按键不卡(统计节流、渲染不再随输入触发)
* **现场**:两工具内输入任意内容,切到文件中心再切回,内容仍在(keep-alive);刷新页面后 JSON 输入不承诺保留、Markdown 草稿保留
* **主题与窄屏**:亮/暗/跟随系统三态下,两工具与预览区排版正常,无主题错乱;窄屏下 Markdown 分栏降级为单栏切换,工具条按钮可键盘聚焦操作

## 9. 二期规划(规划级:方向已定,不排期、本期不实现)

> 实施前按一期同样的流程补细节(逐工具功能表、交互、验收)。与一期共用同一"小工具"模块入口:代码/权限点 `devTools`、check 鉴权、keep-alive、localStorage、纯前端定位均不变;**容器入口形态有变**(由平铺 tab 改为分组下拉,见 §9.2)。

### 9.1 工具清单

**A 组 · 纯前端零依赖(即插即用,无新依赖)**

| 工具 | 功能 | 说明 |
| --- | --- | --- |
| 时间戳转换 | Unix 秒/毫秒 ⇄ 本地/UTC 时间、ISO8601;多行批量换算;正反双向 | 排查服务日志最高频的转换 |
| 编解码 | Base64、URL 组件、HTML 实体、Unicode 转义 编/解(UTF-8 安全) | 调试接口与日志字符串 |
| 生成器 | UUID v4、强密码(长度/字符集可配)、随机 token | `crypto.randomUUID` / `getRandomValues` |
| 进制与颜色 | 2/8/10/16 进制互转;HEX ⇄ RGB ⇄ HSL | 调色板、掩码计算 |
| 字符串整理 | 大小写转换、去首尾空白、去重、排序、CRLF ⇄ LF | 处理 Windows/Unix 文件混用 |

### 9.2 定位与边界

* 二期工具与一期同定位:**纯前端、数据不出浏览器**;仍只有一个后端接口(check),权限点仍 `devTools`,不再新增后端口径
* 明确**不做**服务端能力类工具(HTTP 请求调试、连通性/延迟测速、端口探测)——它们需要新增接口与权限细分(可能限定 developer),若要实现另起需求,不并入本模块二期
* **安全上下文前提**:生成器用 `crypto.randomUUID`、Hash 用 `crypto.subtle`,二者都要求安全上下文(HTTPS/localhost)。平台当前实际只能以 HTTPS 访问(API 端口仅 HTTPS,HTTP 页面无法工作),故可用;**若将来支持 HTTP 访问,这两个工具须提示"当前环境不支持"而非报错**
* localStorage 键:一期既有键 `zimo-dev-tools:markdown-draft` **保持不变**(改名会丢老草稿);二期新键统一 `zimo-dev-tools:<工具>:<项>`(三段);无过期策略、登出不清理(与一期口径一致)
* 新依赖入 package.json 前核对版本与产物体积(同决策 4 对高亮库的顾虑);带非文本资源(如 `.wasm`)的库须先确认资源落在平台静态白名单目录内(见设计 §10.1)
* **容器结构(二期开工前先落地)**:二期工具总数 14 个,顶部 tab 平铺放不下(窄屏更甚)——容器改为**分组下拉**(按分组呈现的单个下拉 + 内容区),**A 组落地前先落地该结构**,不沿用平铺 tab
* **工具按需加载**:各工具用动态 `import()`,切到该 tab 才加载自己的 chunk 与依赖(不因打开"小工具"而下载全部工具与依赖);加载后由 keep-alive 常驻
* **现场保留口径(已定)**:容器内 keep-alive **不设上限**,打开过的工具全部常驻、切回即恢复现场;接受其内存占用。**已知风险**:文本型工具单实例为 KB~MB 级,但图片工具持有位图/Canvas,单实例可能达数十 MB —— 若实测占用过高,再评估对图片类工具单独按需淘汰
* **深链接**:容器支持 `?tool=<工具key>`(便于收藏与回跳),切换工具时同步 query;无参数时取第一个工具

### 9.3 落地顺序建议(不承诺)

按"零依赖 A 组先落地 → 小库 B 组按需引入"的顺序分批;每批先补需求细节与验收再实施,沿用一期 §8 的通用项。

### 9.4 验收

二期逐工具实施时补充;通用项沿用一期 §8(主题三态、现场保留、窄屏、鉴权与权限复检),并新增以下通用项:

* **纯前端校验**:除 ① `check` 接口、② 本站静态资源(按需加载的 JS/CSS chunk)与 ③ 源文内容触发的远程图片(一期 §7 已声明)之外,进入任一工具后**不得产生任何网络请求**——尤其不得请求外部域名、远程字体、埋点或第三方接口;可用浏览器网络面板或自动化断言核验
* **大内容降级通用**:设计文档 §8 决策 28/29/30/31(字符数阈值口径、空闲渲染带 timeout、超限暂停自动处理 + 手动刷新、统计节流零分配)对二期所有输入型工具生效,逐工具给出各自阈值
* **现场保留(二期口径)**:打开过的工具全部保留现场(容器 keep-alive 不设上限,见 §9.2)
