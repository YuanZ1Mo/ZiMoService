状态与错误处置

五个状态覆盖全部界面文案;错误在拉片循环里随时可能出现 —— 收敛动作必须写在播放器里,不能只看握手结果
状态行是唯一状态出口

边界态(不进状态机,进入即不再启动播放)

这两类情形必须在点开始之前或之后立即给出明确结果,不做"看起来在播其实没声音"的静默降级

不支持的浏览器

当前浏览器不支持实时收听,请在安卓 Chrome(或同内核浏览器)中打开。

403 / 401 的处置
403立即停止播放并释放媒体元素;回到空闲,按钮保留(再点仍是 403)
401提示并跳登录(带回跳 /portal/server-audio-stream)
触达拉片每秒多次、每次都鉴权 → 权限收回后 ≤1 批内收敛
提示用壳层 inject('toast'),不写模块私有弹窗
退避 1s → 2s → 4s → 8s(上限)
恢复后跳到直播边缘
媒体元素继续播完已缓冲内容
弱网 / 断网的三条不变量
退避拉片失败 1s 起 ×2,上限 8s;成功后按 X-Next-Poll-Ms 恢复节奏
不补课恢复后跳回直播边缘,不"补听"断网期间的旧内容
不退避连续拿到 0 片是正常情况(还没生成新片),按建议等待即可
错误码与前端处置(逐条实现)
情形前端行为状态行/提示
401 会话已失效提示并跳登录(带回跳);自写的 fetch 要自己判,不能只靠 client.js会话已失效 · 正在跳转登录
403 权限不足立即停止播放并释放媒体元素;回到空闲,保留按钮权限不足,收听已停止
410 STREAM_GONE重新握手(旧 MediaSource 结束并重建),seq 从新的 X-Live-Seq 起状态不变,参数行提示一次
410 SEGMENT_GONE不清缓冲,把 seq 跳到 X-Live-Seq 附近继续拉,让浏览器自己跳过空洞状态不变,参数行提示一次
503 AUDIO_NO_DEVICE状态置无设备,停止拉片,回到空闲(按钮可重试)服务器无可用音频设备
网络异常 / 超时指数退避重连;媒体元素继续播完已缓冲内容连接中断,重连中…(附原因)
连续 0 片正常:按 X-Next-Poll-Ms 等待,不加退避、不当故障状态不变
无障碍与可达性(交付前自查)
单一状态出口

状态行 role="status" aria-live="polite" aria-atomic="true":只播报完整语义("正在播放"),不播报裸数字;状态变化不移动焦点。

键盘与焦点

主按钮与滑杆均可用键盘操作,:focus-visible 有可见环(主按钮 4px 光环);主按钮 aria-label 随状态切换(开始/停止/取消/重试)。

降低动态

prefers-reduced-motion: reduce 时特效静止(画布只画一帧),功能与播放不受影响;呼吸光环等只做 transform/opacity。

对比度双主题

舞台恒为深底、文字 #F1F5F9 以上;信息卡正文 ≥4.5:1;亮暗两套令牌都要实测,状态色不单独承载信息(配文案与图标)。

触达尺寸

主按钮 138px、滑杆高 26px、图标按钮 36px;移动端不出现横向滚动,内容单列排布。

文案即契约

五态文案照抄需求/交接表格实现,不做同义改写 —— 联调与验收按文案逐条核对。
