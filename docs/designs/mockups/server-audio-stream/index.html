③ 设计决策(评审要点)

1舞台恒为深底

亮暗两主题下舞台都保持深色 —— 声音是唯一主角,律动与发光成为焦点;信息卡跟随壳主题,保证表单类对比度 ≥4.5:1。

2单一状态出口

所有状态只从状态行表达(role="status" + aria-live="polite");状态变化不移动焦点,读屏播报完整语义而非裸数字。

3特效不碰音频

画布按播放时间驱动(呼吸/放射律动),禁止 WebAudio 分析;DPR 计算、resize 与 onActivated 重算,reduced-motion 时静止。

4单列 + 约束宽度

手机与桌面同一套布局:桌面居中 720px,不出现横向滚动;参数行与收听信息自然换行,主按钮触达区 138px。

5音量是相对的

滑杆作用于 audio.volume(默认 100、不记忆);文案说明"相对系统音量、手机也可用音量键",不试图接管系统音量。

6收听信息两级

人数人人可见;账号/设备/IP/落后量仅 level ≥ 2。前端按"字段是否存在"决定渲染,不自己判权限。

7后台边界如实说

页面明说:锁屏/切后台可继续听;关闭页面、系统回收、手机重启后不会继续;安卓建议"添加到主屏幕"。

8延迟可解释

参数行的延迟按 X-Edge-Ms − currentTime×1000 折算、每秒刷新;并标注 200~500ms 为正常区间,避免被当成故障。
