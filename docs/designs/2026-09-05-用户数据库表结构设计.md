# 用户数据库表结构设计

> 状态:待审阅 · 版本:v1 · 日期:2026-09-05
> 范围:定义用户系统(账号/会话/安全/权限/审计)的数据库表结构
> 前置:从通用设计出发,不参考历史业务与代码;待需求评审后据此实现

***

## 1. 设计目标与约定

### 1.1 目标

* 单库承载用户域全部数据(库名建议 `user.db`),结构清晰、职责单一
* 账号与密码态集中在 `users`,扩展资料独立成表,避免主表膨胀
* 安全相关(锁定/限流/安全事件)与认证(会话/找回令牌)分表,便于按不同周期清理
* 权限采用"角色 + 单人覆盖"模型,满足模块级授权(门户模块开/关)需求
* 审计(操作/登录)独立落库,支持安全追溯

### 1.2 约定

| 项 | 约定 |
| --- | --- |
| 主键 | 每表自增 `id BIGINT`,内部行号,不对外 |
| 业务 ID | `uid BIGINT` 为账号唯一身份(如 10000001 起递增),各业务模块统一引用 `uid`,账号可改、uid 不变 |
| 时间 | 一律 `INTEGER` unix 秒,字段名 `*_time` / `*_at` |
| 文本编码 | UTF-8;账号/昵称/密码等入库前统一 NFC 归一化 |
| 登录标识 | 支持 account / email / phone 任一登录;登录时统一归一化(`login_key`):account 小写、email 小写、phone 去格式 |
| 敏感存储 | 密码/救援码/令牌一律**哈希落库**(加盐),不存明文 |
| 删除 | 用户走软删除(`deleted` 标记);其余表超期物理清理 |
| 命名 | snake_case;表名复数、字段名单数语义 |

## 3. 表结构定义

### 3.1 `users` 用户主表

| 字段 | 类型 | 约束 | 说明 |
| --- | --- | --- | --- |
| `id` | BIGINT | PK AUTOINCREMENT | 内部行号 |
| `uid` | BIGINT | NOT NULL UNIQUE | 对外业务唯一身份(10000001 起递增),稳定映射键 |
| `account` | VARCHAR(30) | NOT NULL UNIQUE | 登录名,统一小写 `[a-z0-9_-]{4,30}`,首尾非 `_`/`-` |
| `nickname` | VARCHAR(20) | NOT NULL | 显示昵称(默认与 account 一致) |
| `email` | VARCHAR(255) | NULL UNIQUE | 邮箱(找回/通知渠道,可空) |
| `phone` | VARCHAR(20) | NULL UNIQUE | 手机号(可空) |
| `pass_salt` | BLOB | NOT NULL | 密码盐(16B 随机) |
| `pass_hash` | BLOB | NOT NULL | 密码哈希(PBKDF2-HMAC-SHA256,600k 迭代,dklen 32) |
| `status` | TINYINT | NOT NULL DEFAULT 1 | 1=正常 2=已停用 |
| `deleted` | TINYINT | NOT NULL DEFAULT 0 | 0=正常 1=软删除 |
| `register_ip` | VARCHAR(64) | NOT NULL | 注册 IP |
| `register_time` | INTEGER | NOT NULL | 注册时间 |
| `last_login_ip` | VARCHAR(64) | NOT NULL DEFAULT '' | 最近登录 IP |
| `last_login_time` | INTEGER | NOT NULL DEFAULT 0 | 最近登录时间 |
| `force_change` | TINYINT | NOT NULL DEFAULT 0 | 1=需强制改密(管理员重置后置位) |
| `temp_pass_salt` | BLOB | NULL | 管理员重置的临时密码盐 |
| `temp_pass_hash` | BLOB | NULL | 管理员重置的临时密码哈希 |
| `role_code` | VARCHAR(32) | NOT NULL DEFAULT 'user' | 当前角色(单角色模型,引用 `roles.code`) |
| `create_time` | INTEGER | NOT NULL | 记录创建时间(与 register_time 冗余,建行即注册) |

索引:`uid`(唯一)、`account`(唯一)、`email`/`phone`(唯一)。

> 说明:`role_code` 采用单角色字段而非关联表,因为角色是低变更、单值的;如需多角色再迁移到 `user_roles` 关联表。

### 3.2 `user_profile` 用户资料表

| 字段 | 类型 | 约束 | 说明 |
| --- | --- | --- | --- |
| `id` | BIGINT | PK AUTOINCREMENT | 内部行号 |
| `uid` | BIGINT | NOT NULL UNIQUE FK→users.uid | 唯一关联用户 |
| `avatar` | VARCHAR(255) | NOT NULL DEFAULT '' | 头像 URL/路径 |
| `signature` | VARCHAR(200) | NOT NULL DEFAULT '' | 个性签名 |
| `preferences` | TEXT | NULL | 偏好 JSON(主题/语言/每页条数等) |
| `updated_at` | INTEGER | NOT NULL | 最近修改时间 |

> 说明:低频、大字段、展示类数据放此表,随 `users` 同生共死(注册时一并建行)。

### 3.3 `sessions` 会话表

| 字段 | 类型 | 约束 | 说明 |
| --- | --- | --- | --- |
| `id` | BIGINT | PK AUTOINCREMENT | 内部行号 |
| `token_hash` | VARCHAR(64) | NOT NULL UNIQUE | 会话令牌哈希(签发明文 32B 随机,落库存 SHA-256) |
| `uid` | BIGINT | NOT NULL FK→users.uid | 归属用户 |
| `create_ip` | VARCHAR(64) | NOT NULL | 签发 IP |
| `ua` | VARCHAR(255) | NOT NULL DEFAULT '' | User-Agent/设备标识(异地登录提示用) |
| `create_time` | INTEGER | NOT NULL | 签发时间 |
| `last_active` | INTEGER | NOT NULL | 最近活跃(续期依据) |
| `expire_time` | INTEGER | NOT NULL | 滑动过期(如 30 天,活跃则顺延) |
| `absolute_expire` | INTEGER | NOT NULL | 绝对过期(如 90 天,强制重登) |

索引:`token_hash`(唯一)、`uid`。

> 说明:
> - 会话签发:每次登录/注册/重置签发全新 token(与旧 token 不同);**旧会话保持有效**,账号内多会话并发(模型二)
> - 每账号活跃会话上限(如 5 个),超出按 `last_active` 踢最旧(LRU);被动过期仍受 30/90 天双上限约束
> - cookie 名 `zm_session`,Max-Age 与绝对过期对齐

### 3.4 `password_reset_tokens` 找回密码令牌表

| 字段 | 类型 | 约束 | 说明 |
| --- | --- | --- | --- |
| `id` | BIGINT | PK AUTOINCREMENT | 内部行号 |
| `uid` | BIGINT | NOT NULL FK→users.uid | 归属用户 |
| `token_hash` | VARCHAR(64) | NOT NULL UNIQUE | 一次性令牌哈希(不存明文) |
| `create_ip` | VARCHAR(64) | NOT NULL | 签发 IP |
| `create_time` | INTEGER | NOT NULL | 签发时间 |
| `expire_time` | INTEGER | NOT NULL | 过期时间(如 30 分钟) |
| `used_at` | INTEGER | NULL | 使用时间(一次性:非空即作废) |
| `status` | TINYINT | NOT NULL DEFAULT 0 | 0=有效 1=已用 2=已作废 |

索引:`token_hash`(唯一)、`uid`。

> 说明:签发新令牌时先将该用户旧令牌置为 2(作废),保证同时仅一个有效令牌。

### 3.5 `login_locks` 登录锁定表

| 字段 | 类型 | 约束 | 说明 |
| --- | --- | --- | --- |
| `id` | BIGINT | PK AUTOINCREMENT | 内部行号 |
| `uid` | BIGINT | NULL FK→users.uid | 主锁定维度:能解析出用户时填充(密码错误/停用等场景) |
| `login_key` | VARCHAR(64) | NOT NULL | 兜底锁定维度:归一化登录标识(account 小写 / email 小写 / phone 去格式),标识不存在时使用 |
| `ip` | VARCHAR(64) | NOT NULL | 来源 IP |
| `fail_count` | INTEGER | NOT NULL DEFAULT 0 | 连续失败次数(阶梯递增依据) |
| `locked_until` | INTEGER | NOT NULL DEFAULT 0 | 锁定截止(0=未锁定) |
| `last_fail_at` | INTEGER | NOT NULL DEFAULT 0 | 最近失败时间(窗口判断) |

索引:`UNIQUE(uid, ip)`、`UNIQUE(login_key, ip)`、`locked_until`(清理扫描)。

> 说明(记录与查询同一套定位逻辑):
> - 登录标识能解析出用户 → 锁定键 = `uid`(写 uid 列,login_key 冗余记录原始标识备查),**防同一用户换登录标识绕过**
> - 解析不出(标识不存在/未注册)→ 锁定键 = `login_key`(uid 留空),**防账号枚举**
> - 查询锁定:先按 uid 定位,命中则不看 login_key;否则按 login_key 定位
> - 阶梯:每 5 次失败升一档;档 1 锁 15 分钟,档 2+ 锁 60 分钟(封顶)
> - 锁定中不再校验密码、不再计数;成功后清零
> - IP 层的暴力兜底由 `rate_limits` 与账号/用户封禁承担,本表不背全部责任

### 3.6 `rate_limits` 限流表

| 字段 | 类型 | 约束 | 说明 |
| --- | --- | --- | --- |
| `id` | BIGINT | PK AUTOINCREMENT | 内部行号 |
| `scope` | VARCHAR(32) | NOT NULL | 场景:register / reset / login / verify_code |
| `dimension` | VARCHAR(16) | NOT NULL | 维度:`ip` / `uid` / `login_key` / `device` |
| `dim_key` | VARCHAR(128) | NOT NULL | 维度键值(IP 地址 / uid 字符串 / 归一化登录标识 / 设备指纹) |
| `window_start` | INTEGER | NOT NULL | 当前滑动窗口起点 |
| `count` | INTEGER | NOT NULL DEFAULT 0 | 窗口内计数 |

索引:`PRIMARY KEY(scope, dimension, dim_key)`。

> 说明:
> - 单表 + 通用维度键替代"每场景一张表"与"固定 IP 列":**每场景可配置多个维度规则,任一超限即拒绝**
> - 场景默认维度组合(可按需增删):
>   - `register` → [ip, device];手机号注册天然受"每号唯一"约束,无需额外限流
>   - `reset` → [login_key, ip]
>   - `login` → [login_key, ip](可扩展 `uid` 维度,防同一用户高频尝试)
> - IP 仅作基础防线:解决共享 NAT 出口误伤、代理池绕过、固定 IP 用户被误伤等问题,必须叠加用户/设备维度
> - 滑动窗口(如 60s,默认 20 次);窗口滑过自然恢复
> - 落库持久化,重启不丢计数

### 3.7 `security_events` 安全事件表

| 字段 | 类型 | 约束 | 说明 |
| --- | --- | --- | --- |
| `id` | BIGINT | PK AUTOINCREMENT | 内部行号 |
| `uid` | BIGINT | NULL FK→users.uid | 相关用户(未登录场景可空) |
| `account` | VARCHAR(30) | NOT NULL DEFAULT '' | 账号快照(未登录时记录输入账号) |
| `event_type` | VARCHAR(32) | NOT NULL | 事件类型(见下) |
| `ip` | VARCHAR(64) | NOT NULL DEFAULT '' | 来源 IP |
| `ua` | VARCHAR(255) | NOT NULL DEFAULT '' | UA |
| `detail` | TEXT | NULL | 详情 JSON(如上下文/参数) |
| `create_time` | INTEGER | NOT NULL | 事件时间 |

索引:`uid`、`event_type`、`create_time`。

> 事件类型建议枚举:`login_anomaly`(异地/异常时段登录)、`brute_force`(疑似爆破)、`password_changed`、`admin_reset`、`force_change`、`bind_changed`(邮箱/手机变更)、`permission_denied`(越权尝试)。

### 3.8 `roles` 角色定义

| 字段 | 类型 | 约束 | 说明 |
| --- | --- | --- | --- |
| `id` | BIGINT | PK AUTOINCREMENT | 内部行号 |
| `code` | VARCHAR(32) | NOT NULL UNIQUE | 角色编码(developer / admin / user) |
| `name` | VARCHAR(32) | NOT NULL | 显示名(开发者/管理员/用户) |
| `level` | TINYINT | NOT NULL | 等级(3/2/1),等级压制规则:操作者等级必须 > 目标 |
| `permission_codes` | TEXT | NOT NULL DEFAULT '[]' | 角色包含的权限点 code 集合(JSON 数组) |
| `sort` | TINYINT | NOT NULL DEFAULT 0 | 排序 |
| `builtin` | TINYINT | NOT NULL DEFAULT 0 | 1=内置角色,禁止删除/改 code |
| `description` | VARCHAR(200) | NOT NULL DEFAULT '' | 描述 |
| `updated_at` | INTEGER | NOT NULL | 最近修改时间 |

索引:`code`(唯一)。

> 说明:
> - 角色权限点少、变更低频,`permission_codes` 字段化(JSON 数组)替代 `role_permissions` 关联表,查询一次到位
> - 若未来权限点膨胀、需要独立审计角色授权变更,可迁移为 `role_permissions` 关联表(字段化数据可一键拆行)
> - `level` 支撑"仅可操作比自己低级的账号、角色提升最高到自己的下一级"

### 3.9 `permissions` 权限点定义

| 字段 | 类型 | 约束 | 说明 |
| --- | --- | --- | --- |
| `id` | BIGINT | PK AUTOINCREMENT | 内部行号 |
| `code` | VARCHAR(64) | NOT NULL UNIQUE | 权限点编码(模块级如 `filehub`;资源级如 `filehub:delete`) |
| `name` | VARCHAR(64) | NOT NULL | 显示名(如"文件中心") |
| `module` | VARCHAR(64) | NOT NULL DEFAULT '' | 所属模块(空=系统级;门户导航按此分组) |
| `url` | VARCHAR(128) | NOT NULL DEFAULT '' | 门户模块路由(如 `/portal/filehub`) |
| `type` | TINYINT | NOT NULL DEFAULT 0 | 0=模块级(进入模块即视为拥有) 1=资源级(细分动作) |
| `index` | INT | NOT NULL DEFAULT 0 | 门户模块排序索引:正数从 1 起、越小越靠前;负数从 -1 起、永远排在正数之后、数值越大越靠前(-1、-2、-3…);0/空=非门户模块,不参与导航排序 |
| `sort` | TINYINT | NOT NULL DEFAULT 0 | 同类权限点内的次要排序(与 `index` 职责分离) |
| `enabled` | TINYINT | NOT NULL DEFAULT 1 | 0=停用(前端不显示,判定视为无权限) |
| `description` | VARCHAR(200) | NOT NULL DEFAULT '' | 描述 |

索引:`code`(唯一)、`module`。

> 说明:门户模块即权限点(种子:`home`/`filehub`/`serverAudioStream`/`userManager`/`filehubAdmin`),模块的 URL 与排序由本表驱动侧边栏与授权弹窗。

### 3.10 `user_permissions` 单人额外授权

| 字段 | 类型 | 约束 | 说明 |
| --- | --- | --- | --- |
| `id` | BIGINT | PK AUTOINCREMENT | 内部行号 |
| `uid` | BIGINT | NOT NULL FK→users.uid | 目标用户 |
| `perm_code` | VARCHAR(64) | NOT NULL FK→permissions.code | 权限点 |
| `grant_type` | TINYINT | NOT NULL DEFAULT 1 | 1=授予(白名单式追加) 2=拒绝(黑名单式覆盖) |
| `grant_by` | BIGINT | NULL FK→users.uid | 授权人(管理操作审计联动) |
| `create_time` | INTEGER | NOT NULL | 授权时间 |

索引:`UNIQUE(uid, perm_code)`。

> 说明:
> - 用于"角色之外给个别用户单独开/关某模块",不污染角色定义
> - 典型场景:普通用户临时获得 `filehubAdmin`;或从某角色临时收回某个模块
> - 拒绝(grant_type=2)优先级最高,可覆盖角色默认权限

### 3.11 `operation_logs` 操作审计表

| 字段 | 类型 | 约束 | 说明 |
| --- | --- | --- | --- |
| `id` | BIGINT | PK AUTOINCREMENT | 内部行号 |
| `operator_uid` | BIGINT | NOT NULL FK→users.uid | 操作者 |
| `operator_account` | VARCHAR(30) | NOT NULL | 操作者账号快照(防改名后不可追溯) |
| `action` | VARCHAR(32) | NOT NULL | 动作(disable / enable / reset_password / change_role / grant_permission / delete 等) |
| `target_type` | VARCHAR(32) | NOT NULL | 目标类型(user / role / permission) |
| `target_id` | BIGINT | NOT NULL | 目标 id |
| `detail` | TEXT | NOT NULL DEFAULT '' | 变更详情 JSON(如 {role:"admin"}、{permissions:[...]}) |
| `ip` | VARCHAR(64) | NOT NULL DEFAULT '' | 操作来源 IP |
| `create_time` | INTEGER | NOT NULL | 操作时间 |

索引:`operator_uid`、`target_type+target_id`、`create_time`。

### 3.12 `login_logs` 登录日志表

| 字段 | 类型 | 约束 | 说明 |
| --- | --- | --- | --- |
| `id` | BIGINT | PK AUTOINCREMENT | 内部行号 |
| `uid` | BIGINT | NULL FK→users.uid | 成功登录才有值 |
| `account` | VARCHAR(30) | NOT NULL | 尝试登录的账号 |
| `result` | TINYINT | NOT NULL | 1=成功 2=失败 |
| `fail_reason` | VARCHAR(64) | NOT NULL DEFAULT '' | 失败原因(密码错误/账号锁定/账号不存在/限流) |
| `ip` | VARCHAR(64) | NOT NULL | 来源 IP |
| `ua` | VARCHAR(255) | NOT NULL DEFAULT '' | UA |
| `create_time` | INTEGER | NOT NULL | 时间 |

索引:`account`、`create_time`。

> 说明:量大,与 `operation_logs` 分表存放;保留期更短(30~90 天),定期批量清理。

## 4. 权限判定模型

### 4.1 判定规则

```
有效权限(perm) =
    角色默认:roles.permission_codes 中该用户的 role_code 对应集合
  ∪ user_permissions 授予(grant_type=1)的集合
  − user_permissions 拒绝(grant_type=2)的集合
```

优先级:**拒绝 > 角色默认 > 额外授予**。判定在内存缓存后按会话续期周期刷新,避免每请求查库。

### 4.2 门户模块授权(导航与拦截)

1. 登录/进入门户时按上述规则计算可见模块集 → 渲染侧边栏
2. 模块级权限点(`type=0`):拥有 `filehub` 权限点才允许访问 `/portal/filehub`(前端路由 + 服务端接口双重拦截)
3. 管理型模块(如 `userManager`/`filehubAdmin`):作为权限点授予即可,不再依赖角色名写死

### 4.3 等级压制(用户管理操作)

`users.role_code → roles.level`;仅当 `操作者.level > 目标.level` 时允许停用/删除/重置/改角色等管理操作;角色提升最高到操作者的下一级。

## 6. 清理与保留策略

| 表 | 保留期 | 触发 |
| --- | --- | --- |
| sessions | 过期即清(双上限到期) | 每日窗口 |
| password_reset_tokens | 过期即清;签发时作废旧令牌 | 每日窗口 |
| login_locks | 7 天无动静即清 | 每日窗口 |

## 7. 设计取舍说明

| 取舍 | 理由 | 迁移路径(如未来需要) |
| --- | --- | --- |
| 单角色字段 `users.role_code` | 角色单值、低变更 | 拆 `user_roles` 关联表支持多角色 |
| 角色权限 `roles.permission_codes` 字段化 | 权限点少、查询一次到位 | 拆 `role_permissions` 关联表 |
| 单人授权 `user_permissions` 支持拒绝 | 覆盖"临时收回/特批"场景 | — |
| `rate_limits` 单表 + 通用维度键(scope×dimension×dim_key) | 固定 IP 维度误伤 NAT/固定用户、易被代理绕过 | 维度规则过多时按 scope 分区/分表 |
| 找回密码走令牌表 | 支持邮件/短信链接,替代单一救援码 | 与救援码方案可并存 |
| 安全事件独立成表 | 审计日志只记录已发生事实,事件表承载风控信号 | — |
