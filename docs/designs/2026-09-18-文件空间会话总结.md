## 2. 已实现功能(对照需求)

* **空间**:公共/个人双空间、个人空间懒创建(库行 + 目录)、只下发"公共 + 本人"、个人空间仅本人可写;
* **浏览**:列表(目录恒在前、排序/分页/类型与时间筛选)、面包屑、详情(含相对路径)、搜索(递归、500 截断 + `truncated` + `path`、按层级与时间排序);
* **操作**:新建(名称/保留名/深度/长度校验)、改名、移动(跨空间、环路检测、祖先折叠、冲突 ask/skip/rename/overwrite、原地不动跳过)、复制(同左 + >500 条或 >1GB 转异步任务)、软删除;
* **回收站**:列表(强制 `del_owner_uid = 操作者`)、恢复(原位不可用回根 + 自动重命名)、彻底删除(先物理后删行,失败整条保留)、清空(异步任务 type=6)、保留期 30 天、同名不占位;
* **上传**:单请求(头元数据 + 原始字节,≤64MB)、分片(8MB/片、断点续传、3 并发闸门)、秒传(同空间 hash+size)、冲突裁决、会话 24h TTL、过期/中断回收;
* **下载**:令牌(32 字符高熵、10 分钟、(uid|share_token, node) 绑定)、Range/416/If-Range、RFC 5987 中文名、**raw 流式 + 软件水位**、令牌级 ≤5 与全局 ≤100 名额(按在途传输精确计数)、下载审计;
* **打包**:minizip-ng(deflate 1 / 已压缩格式 store)、UTF-8 标志位、空目录保留、进度/取消、空闲 30 分钟回收、24h 兜底、50GB→80% 容量保护;
* **任务**:6 类型 6 状态、`tasks/active` 单接口轮询、取消(排队直接置位/进行中标记)、重试(进程内输入)、清除历史、僵尸清理、启动中断标记;
* **分享**:创建/修改/取消、提取码(仅存 HMAC、明文一次性、(IP,token) 5 次错码冷却)、有效期/下载次数/仅登录、公开面免会话 + `zm_share` 凭证 Cookie、`need_login` 401、打包下载 `task_no` **幂等重试**、单用户 200 上限、访问日志脱敏;
* **管理端**:概览统计(含 Top 用户昵称)、一致性同步(磁盘为准、只补库删行、回收站交界、dry_run、取消、实时进度、`scanned_items`/`total_dirs`)、缓存列表与清理、全量回收站(恢复/彻底删除/**整体清空**/保留期清理)、全量任务与强制取消、审计与分享日志、空间配额;
* **横切**:权限点 `filehub`/`filehubAdmin` 幂等登记、门禁白名单、审计与业务同事务、周期清理 9 项。

## 4. 目前存在的问题与风险

1. **部署状态未确认**:生产服务当前跑的是哪个构建,本会话不掌握(方案 C + 水位的最终构建在 `A:\ZiMo\temp_build_out\ZiMoService.exe`;`Release\workspace\ZiMoService.exe` 是 09-17 早些时候的版本)。前端 `USE_MOCK` 是否已切 `false` 同样待确认。
2. **全局下载并发上限 100 未按实测标定**:慢客户端会**长期占用名额**(水位只压内存、不因慢而断开),大量慢链路场景下 100 偏大,建议按实测下调到 16~32。
3. **水位是近似实现**:用连接 `bytesSent()` 增量近似排水量(连接级累计,含响应头/TLS/上一响应残余)→ 偏松;同连接管道化多响应时偏差明显(本平台不产生管道化)。
4. **名额归还的兜底是 30 秒巡检**:客户端在"响应开始发送前"断开时,靠巡检回收(最长占位 30 秒);正常路径由平台 `onFinish` 精确归还。
5. **写操作顺序与需求 §3.3/§3.4 相反**:一律"物理先 → DB + 审计同事务 → 失败物理回滚",回滚失败只记 ERROR 交由一致性同步修复。
6. **打包/上传闸门是进程内状态**:重启即重建;`WaitPackSlot` 200ms 轮询排队。
7. **`filehub.db` 建库后不做迁移**:改表由运维手工执行 SQL(与 user.db 现状一致)。
8. **一致性同步进度分母是"库中目录数"**:磁盘多出的目录会让 `scanned` 超过 `total`(前端按 100% 截断)。
9. **慢链路之外的观测盲区**:未在真实公网/多客户端混合负载下压测过。

## 5. 下一个 AI 必须知道的坑(踩过才总结出来的)

| # | 坑 | 结论 |
| --- | --- | --- |
| 1 | **契约口径** | 后端字段以 `frontend/src/api/filehub-mock.js` 为准(用户拍板);发现 Mock 与文档冲突时按文档实现并在交接文档 §3.2 记录 |
| 2 | **下载绝不能用文件节点路径** | `SendFileHybridCoro`/`newFileResponse` 分支在 Windows 下**读盘在事件循环上**(24 路并发实测卡 2866/322ms);必须走 `SendFileStreamCoro`(读盘在 `ZmHttpIo` 池)+ `raw=true` + `watermarkBytes` |
| 3 | **水位不能少** | 无水位时慢客户端会把整份文件堆进内存(2GB 文件 + 3MB/s 实测 3.5GB);有水位 34.8MB |
| 4 | **名额归还要配对** | 正常靠 `ZmHttpSendFileOptions::onFinish`;改下载路径时勿丢;`resp->asyncStreamCallback()` 为空(=304/416/404 早退)时要在 handler 里立即 `Release` |
| 5 | **drogon 本地补丁** | `ResponseStream::sendRaw/closeRaw` 是纯内联新增(不改布局、不重编 lib);升级 drogon 要重新贴 |
| 6 | **内存观测** | `tasklist` 的内存列带千分位逗号,`cut -d, -f5` 会读错(把 3.5GB 读成 20MB);用 `awk -F'","' '{print $5}'` |
| 7 | **测试环境配方** | 副本到 `ZiMoTest\ZiMoServiceTestEnv`(跳过 db)、改三处端口(net_dock 39440/39441、frontend 443/80、重定向 443)、exe 改名隔离日志、`sc create ZM_SvcTest` 临时服务、**生产不停** |
| 8 | **端口改动必须逐处还原** | 不能用 `git checkout` 整文件(可能含未提交改动);改完 grep `TEST-PORT` 应为 0 |
| 9 | **测试脚本每次先 reset** | `filehub_test_reset.sh` 清 db + 重建账号;不 reset 会出"同名冲突/计数不符"的假失败 |
| 10 | **中文 body 用文件** | `curl --data-binary @file`(printf 写文件);直接 `-d` 会被 shell 编码毁掉 |
| 11 | **MSBuild 调用** | `MSYS_NO_PATHCONV=1`,路径 `D:\...\MSBuild.exe`;生产服务锁 exe → 要么停服务,要么 `/p:OutDir=A:/ZiMo/temp_build_out/`(正斜杠) |
| 12 | **批量编辑源码** | 用 python/heredoc 改 C++ 时反斜杠与 `\1` 极易被 shell/Python 吃掉(本会话曾把缩进毁成单空格,靠 `clang-format` + 项目风格参数救回);优先用 Edit 工具精确替换 |
| 13 | **用户会自己提交** | 提交信息是 `cache`;不要擅自 commit/push,也不要假设工作区等于上次阅读状态(每次都先 `git status`) |

## 6. 自测体系(怎么跑)

```bash
sh /a/ZiMo/ZiMoAiscript/filehub_test_reset.sh          # 每次先重置环境 + 登录(必须)
for s in ab c d e f g h i; do sh /a/ZiMo/ZiMoAiscript/filehub_smoke_$s.sh; done   # 197 项断言
node /a/ZiMo/ZiMoTest/drop_entries_test.mjs            # 前端拖入展开单测 14 项
```

套件覆盖:A/B 浏览与命名规则、C 上传(含分片/秒传/打包)、D 分享全链路、E 管理端与一致性同步、F 边界与并发、G 闸门与重试、H 复核回归、I 下载链路(Content-Length/零分帧/SHA-256/Range/416/断连回收)。

**并发闸门需临时把 `kGlobalDownloadMax` 调到 2 才能直接观测**(本会话验证过:占满 2 路第 3 路 503、结束后放行、断连 1.5 秒内回收),套件 I 不含这一项。
