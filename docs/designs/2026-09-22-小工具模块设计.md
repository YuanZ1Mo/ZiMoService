## 1. 总览

本模块前端为主、服务端极薄:服务端做权限点登记,并提供一个**页面鉴权接口**(会话 + 账号状态 + `devTools` 权限,标准链路),不建表、不涉及文件与媒体面;工具数据全部落在浏览器本地。页面能否进入由服务端接口把关,与文件中心/音频模块的鉴权姿态一致。

```
开发视角下新增的落点:
  服务端  modules/module_dev_tools.{h,cpp}(权限点登记 + check 鉴权接口)
          service_portal.cpp 装配两处 + .vcxproj 两个源文件
  前端    frontend/src/modules/dev-tools/{index,JsonFormat,MarkdownEditor}.vue
          frontend/src/api/devTools.js(check 唯一接口封装)
  门户    PortalLayout.vue icoOf 加 devTools 图标分支
  依赖    package.json 增 marked、dompurify(渲染管线含源文 HTML 转义,见 §5.1)
```

## 2. 服务端设计(权限登记 + 页面鉴权接口)

### 2.1 ZmDevToolsModule

职责:
1. 装配期把 `devTools` 权限点写入 `user.db` 的 `permissions` 表并绑定 `developer` 角色(幂等);
2. 注册唯一接口 `GET /zimo/api/devTools/check`,走与 `ZmServerAudioStreamModule` 完全同构的门禁骨架。

```cpp
// module_dev_tools.h
/**
 * @brief 小工具门户模块:权限点登记 + 页面鉴权接口,工具数据不进服务端
 */
class ZmDevToolsModule
{
public:
    ZmDevToolsModule(ZmHttpRestfulServer* rest, ZmSessionModule* session,
                     ZmPermissionModule* permission, ZmAuthGateModule* gate);
    /// @brief 注册 /zimo/api/devTools/check(页面进入鉴权探测)
    void RegisterRoutes();
    /// @brief 登记 devTools 门户权限点(幂等,绑定 developer 角色)
    void RegisterPermissions();

private:
    /// @brief 标准门禁:会话 + 账号状态 + devTools 权限
    drogon::Task<ZmGateResult> Authorize(const drogon::HttpRequestPtr& req);
    /// @brief GET /zimo/api/devTools/check
    drogon::Task<drogon::HttpResponsePtr> HandleCheck(drogon::HttpRequestPtr req);

    ZmHttpRestfulServer* m_rest       = nullptr;  ///< RESTful 面(装配注入)
    ZmSessionModule*     m_session    = nullptr;  ///< 会话模块(装配注入)
    ZmPermissionModule*  m_permission = nullptr;  ///< 权限模块(装配注入)
    ZmAuthGateModule*    m_gate       = nullptr;  ///< 门禁模块(装配注入)
};
```

```cpp
// module_dev_tools.cpp
constexpr const char* kPermCode      = "devTools";
constexpr const char* kRoutePrefix   = "/zimo/api/devTools";

void ZmDevToolsModule::RegisterRoutes()
{
    if (!m_rest)
    {
        DEFAULT_LOG_ERROR("ZmDevToolsModule: RESTful 面为空,路由未注册");
        return;
    }
    m_rest->RegisterCoro(std::string(kRoutePrefix) + "/check", drogon::HttpMethod::Get,
                         [this](drogon::HttpRequestPtr req) -> drogon::Task<drogon::HttpResponsePtr>
                         { return HandleCheck(std::move(req)); });
    DEFAULT_LOG_INFO("ZmDevToolsModule: 页面鉴权接口已注册({}/check)", kRoutePrefix);
}

void ZmDevToolsModule::RegisterPermissions()
{
    if (!m_permission)
        return;
    ZMJSON perm           = ZMJSON::object();
    perm["code"]          = "devTools";
    perm["name"]          = "小工具";
    perm["module"]        = "portal"; // 分组展示字段,与 home/filehub 一致(不参与侧边栏过滤与鉴权)
    perm["url"]           = "/portal/dev-tools";
    perm["type"]          = 0; // 门户模块:进侧边栏
    perm["index"]         = 4; // 正数区升序:home(1) → filehub(2) → serverAudioStream(3) → devTools(4)
    perm["sort"]          = 7;
    perm["enabled"]       = 1;
    perm["description"]   = "门户小工具集(JSON 格式化 / Markdown 编辑器)";
    bool ok = m_permission->RegisterPermCodeSync(perm, {"developer"});
    if (!ok)
        DEFAULT_LOG_ERROR("ZmDevToolsModule: 权限点登记失败(devTools)");
    else
        DEFAULT_LOG_INFO("ZmDevToolsModule: 权限点已登记(devTools)");
}

// 门禁骨架与音频模块 Authorize 完全同构:取 Cookie → AuthAndTouch → CheckCtxSync → HasPermission
drogon::Task<ZmGateResult> ZmDevToolsModule::Authorize(const drogon::HttpRequestPtr& req)
{
    const std::string cookie = req->getCookie(ZmSessionModule::CookieName());
    ZmGateResult r;
    r.ctx              = co_await m_session->AuthAndTouch(cookie, ZmAuthGateModule::ClientIp(req));
    const ZmGateResult g = ZmAuthGateModule::CheckCtxSync(r.ctx, kRoutePrefix);
    if (!g.ok)
    {
        r.status = g.status; r.code = g.code; r.message = g.message;
        co_return r;
    }
    if (!(co_await m_permission->HasPermission(r.ctx.uid, std::string(kPermCode))))
    {
        r.status = 403; r.code = "PERM_DENIED"; r.message = "无权限访问";
        co_return r;
    }
    r.ok = true;
    co_return r;
}

drogon::Task<drogon::HttpResponsePtr> ZmDevToolsModule::HandleCheck(drogon::HttpRequestPtr req)
{
    const ZmGateResult gate = co_await Authorize(std::move(req));
    if (!gate.ok)
        co_return ZmAuthGateModule::ApiError(gate.status, gate.code, gate.message);
    co_return ZmAuthGateModule::ApiOk(ZMJSON::object());
}
```

* 响应:通过 `ApiOk({})`;**不携带任何工具数据**(check 只回答"能不能进")
* 401/403 语义与文件中心一致:`ApiError(status, code, message)`,前端据此分流——401 `AUTH_REQUIRED`(gate 层或 handler 层返回)、403 `PERM_DENIED`(无 `devTools` 权限)、403 `FORCE_CHANGE_REQUIRED`(强制改密态,由 `CheckCtxSync` 产生)

### 2.2 装配

`service_portal.cpp`:
* `CreateModules()` 中创建 `m_devTools`(依赖 rest / session / permission / gate,与 `m_audio` 同序),文件头与初始化列表同步声明;
* `m_devTools->RegisterRoutes()` 与其余 RESTful 路由同批注册;`RegisterPermissions()` 放在 `m_audio->RegisterPermissions()` 之后(顺序无关,仅保持可读)。

### 2.3 不做的事

* 不建表、不写文件、不涉及 WS / 媒体面;
* 不登记 `module_gate.cpp` 的路径白名单与 `ApiPermForPath` 映射(`RestfulGateAdvice` 对 `/zimo/api/` 只做"无 cookie → 401",细粒度权限由 handler 自检完成;`ApiPermForPath` 当前无调用点,属预留映射表);
* 无心跳 policyVersion 联动(模块清单由权限模块原生驱动)。

## 3. 前端结构

### 3.1 文件与组件树

```
frontend/src/modules/dev-tools/
  index.vue            容器:activeTool 状态 + 顶部 tab(JSON 格式化 | Markdown 编辑器)
  JsonFormat.vue       工具一:JSON 格式化
  MarkdownEditor.vue   工具二:Markdown 编辑器
  stats.js             文本统计口径(§5.7;两工具共用,避免口径漂移)
  dev-tools.css        模块共享样式(dt- 前缀 + .md-body 预览排版)
frontend/src/api/devTools.js   # check()——调用 GET /zimo/api/devTools/check,复用 client.js 的 api 封装(401/403 分流语义见 client.js)
```

* 路由:路径 `/portal/dev-tools` 由 `import.meta.glob('../modules/**/index.vue')` 自动注册,无需改 router
* 挂载:`<component :is>` + `<keep-alive>`(容器内保活,切 tab 不丢现场;门户壳级 keep-alive 保证切模块不丢)
* 样式:复用 `base.css` 令牌变量;工具内部类统一 `dt-` 前缀;预览区排版独立类 `.md-body`(见 §5.6)

### 3.2 权限与鉴权(服务端把关)

* 容器在 **`onMounted` 与每次 `onActivated`** 调用 `devToolsApi.check()`(首次挂载 + 每次从其他模块切回复检);因 keep-alive 下首次挂载也会触发 `onActivated`,需用标志**跳过首次激活**,避免首次进入发两次请求
* 按结果分流:
  * **200** → 挂载工具;
  * **403 且 `code=PERM_DENIED`** → 渲染"无权限访问"占位,**不挂载工具**(切回时若已挂载则卸载工具并切换为占位);
  * **403 且 `code=FORCE_CHANGE_REQUIRED`** → **不渲染占位**(client.js 已 `location.href=/force-reset` 跳改密页,组件只做静默忽略);
  * **401**(未登录/会话失效)→ 交给 `api/client.js` 统一处理(跳登录页,带回跳)
* **首次判定失败**(网络异常等非 401/403 结果):渲染错误态("鉴权检查失败" + 重试按钮),**不误判为无权限**、不留空白页;重试即再次调用 check
* 复检为**静默**执行:已有工具现场时不显示加载态、不清空输入(仅当结果变为无权限才卸载);复检失败按"保持现状"处理,不误判为无权限
* 首帧渲染**骨架/占位**;本地 `hasPerm(code)` 只作**否定快速路径**(本地已确定无权限 → 直接占位,不等 check),本地有权限时**不提前挂载**,统一等 check 200——避免"旧权限快照先挂载、check 回来再卸载"的闪动
* 权限列表异步下发,初始未决时不预判,等 check 结果为准
* **边界声明**:停留在本模块内(不切走、不刷新)期间不轮询,权限撤销不会即时生效——但本模块无数据面、不触服务器,风险仅限继续编辑本地草稿;账号停用/会话失效由门户壳 10s 心跳兜底(401 立即下线、策略版本变化刷新模块清单,侧边栏入口随之消失)。若未来某个工具涉及服务器操作,该工具需按自身接口的逐请求鉴权为准,并考虑周期性复检

### 3.3 响应式与可访问性

* 窄屏(宽度 < 768px):Markdown 分栏降级为单栏,由"编辑 / 预览"分段按钮切换;JSON 左右分栏改为上下堆叠
* 工具条按钮用 `<button>` 元素,带 `aria-label` 与 `title`(含快捷键提示),可 Tab 聚焦并回车触发;焦点样式沿用 `base.css` 的 `:focus-visible`
* 预览区与编辑区文字全部使用 `base.css` 令牌色,亮/暗/跟随系统三态自动适配(对应需求 §8 主题验收)

## 4. 工具一:JSON 格式化

### 4.1 核心处理

```
缩进 = { 2: '  ', 4: '    ', tab: '\t' }             // 空格串/Tab
格式化 = JSON.stringify(JSON.parse(src), null, 缩进)   // 空值/布尔照常,不缩键
压缩   = JSON.stringify(JSON.parse(src))              // 紧凑单行
```

* 解析失败:捕获 `SyntaxError`,按**多格式**从 `err.message` 取位置:
  1. 优先匹配引擎直接给出的 `(line L column C)`(Chrome/V8 新版、Node 均可);
  2. 否则匹配 `at position N`(V8 旧版/精简消息),再回溯输入串换算为 `{line, col}`;
  3. 两者都无(Firefox/Safari 文案不同)→ 不做定位,只展示引擎原文
* 原因文案:内置常见错误映射给出中文说明(意外 token、意外的结尾、缺逗号/缺冒号、键未加引号、单引号字符串、尾随逗号、非法数字、控制字符等);未命中映射时**原样展示引擎 message**(可能为英文),不臆造原因
* 引擎级深层嵌套报 `RangeError`(如 "Maximum call stack")时,提示"内容过大或嵌套过深"
* 精度与安全:`JSON.parse/stringify` 为标准实现,天然可循环安全(可枚举键、BigInt 报错文本化),不使用 `eval` / `Function`
* 输出为空值(`null`/`false`/`0`)时按字面展示,不误判为空输入

### 4.2 输入与交互

* 载入示例:内置一份含嵌套对象/数组/中文/转义字符的示例,点按钮填入输入区并立即重算(当前输入非空时先确认再覆盖)
* 拖入文件:`dragover + drop` 于输入区(必须 `preventDefault` 两事件,否则浏览器会直接打开文件),`FileReader.readAsText`;直接取 `e.dataTransfer.files[0]`(**不走** `api/drop-entries.js` 的目录递归——那是文件中心的多文件语义;拖入文件夹或多文件时只取首个可读文本文件);**不校验扩展名**,按内容解析
* 防抖 300ms 重算;输入为空输出区显示空态;**输入 >2MB 进入大文件模式**:提示"内容较大,已暂停自动重算,请点格式化 / 压缩",同时关闭自动重算(改由按钮触发),避免每次停顿都全量 `parse + stringify` 卡住输入
* 校验失败:右侧**清空并显示错误条**(不保留上一次成功输出,与需求 §3.2"不渲染半成品"一致)
* 复制:`navigator.clipboard.writeText` → 失败逐级回退 `document.execCommand('copy')` → 仍失败则 `select()` 全选输出并提示"已选中,请手动复制";成功/失败均出 toast
* 错误定位:仅在**用户手动触发**(点格式化 / 压缩、载入示例后)时 `setSelectionRange` 到出错字符并 `focus()`;输入态自动重算只更新错误条,**不移动光标、不抢焦点**(否则会打断连续输入);无位置信息时只展示错误条
* 输出回填:把输出覆盖到输入区并重算(等价于"压缩→格式化"肉眼验证,无需单独功能)

### 4.3 组件状态

```
src      输入文本
out      输出文本/错误对象 {line, col, msg}
indent   '2' | '4' | 'tab'
big      大文件模式(输入 >2MB):关闭自动重算
stats    输入/输出 字符数、行数
```

* 大文件模式 `big`(输入 >2MB):置位后关闭自动重算,页脚提示改由按钮触发(见 §4.2);输入回落到 2MB 以下自动恢复自动重算
* JSON 输入**不持久化**(组件态即可):切走不丢由容器级 keep-alive 保证,刷新页面不恢复——与需求 §6 / §8 一致,避免"需求承诺恢复、设计不实现"的落差
* 无外部依赖,全部用标准 JSON API,测试联调零成本。

## 5. 工具二:Markdown 编辑器

### 5.1 依赖与渲染管线

* 依赖:`npm install marked dompurify`(在非沙箱终端执行,随 vite 打进 JS 产物)
* 管线:输入 → **转义源文 HTML** → `marked.parse(src, { gfm: true, breaks: false })` → `DOMPurify.sanitize(html)`(默认配置,剥离脚本/事件处理器)→ `v-html` 注入预览区
* **HTML 转义(需求 §4.2)**:marked 默认直通原始 HTML,与本模块"源文 HTML 一律按文本展示"的要求相悖,必须在渲染器层显式转义(块级与行内 HTML token 同处理),例如 `marked.use({ renderer: { html: (t) => escapeHtml(t.text ?? t.raw) } })`;DOMPurify 作为第二道防线保留
* **换行口径**:`breaks: false`——只认 CommonMark 硬换行(行尾两空格或反斜杠),段落内单换行折叠为空格(与需求 §4.2 一致);若后续要"软换行即换行",改 `breaks: true` 并同步修改需求
* **链接**:自定义 `renderer.link` 输出 `target="_blank" rel="noopener noreferrer"`,避免点击外链把门户 SPA 导航走(丢现场)
* **图片**:允许渲染源文图片;统一补 `referrerpolicy="no-referrer"` 与 `loading="lazy"`(不向图片站暴露本页地址);加载失败显示 `alt` 文本占位
* 渲染时机:输入防抖 300ms;超过 `IDLE_RENDER_CHARS`(10 万**字符**,与统计、解析成本同口径)时把渲染放进空闲时段——`requestIdleCallback(fn, { timeout: 500 })`,**必须带 timeout**,否则页面持续繁忙时回调可能被无限推迟(预览看起来像卡住);不支持 rIC 时回退 `setTimeout(0)`
* **暂停自动预览**:超过 `PAUSE_PREVIEW_CHARS`(26 万字符)不再自动渲染,预览区显示"内容较大,已暂停自动预览" + **「刷新预览」**按钮手动触发一次;回落到阈值以下自动恢复。依据(实测):500KB→870ms、1MB→3.5s,其中 marked 仅占 8%~17%,**DOMPurify + `v-html` 注入占 83%~92%**,且成本随生成的 HTML(1MB 源文→约 3.3MB HTML)超线性增长 —— rIC 只能挪动卡顿时刻,消除不了
* XSS 三保险:源文 HTML 转义 + DOMPurify 清脚本/事件属性 + 预览容器不绑定除链接跳转外的交互事件

### 5.2 分栏与滚动联动

* 模式 `mode: 'edit' | 'preview' | 'split'`:split 时两栏等宽起步,分隔条 `mousedown → mousemove` 改宽度(组件态记录,刷新不回位可接受)
* 滚动联动**单向**(需求 §4.4),仅 split 生效:预览 `scroll` 时按 `ratio = preview.scrollTop / max(1, preview.scrollHeight - preview.clientHeight)` 映射 `edit.scrollTop = ratio * (edit.scrollHeight - edit.clientHeight)`;编辑区滚动**不**反向驱动预览(避免互跳,也避免输入时被抢滚动)
* 联动用 `requestAnimationFrame` 节流(跟手且不在滚动中反复布局);输入过程中不强制滚回

### 5.3 工具条与快捷键(统一入口)

* 唯一实现 `insertMarkdown(pre, post, placeholder)`:
  * 无选区:光标处插入 `pre + placeholder + post`,选中 placeholder 待替换
  * 有选区:对选中文本做 `pre + sel + post` 包裹
  * 表格/分割线等"插入型"动作在光标处整行插入,不包裹
  * 操作后焦点回到光标/选区末尾
* 工具条按钮与 §4.3 快捷键表共用同一动作表;`keydown` 集中处理全部组合:`Ctrl/Cmd+B`(加粗)、`I`(斜体)、`E`(行内代码)、`U`(删除线)、`K`(链接)、`Shift+K`(图片)、`` ` ``(代码块)、`Alt+1/2/3`(H1~H3)、`S`(立即保存)
* **所有已绑定组合一律 `preventDefault`**(尤其 `Ctrl+U` 查看源码、`Ctrl+Shift+K` 在 Firefox 是开发者控制台、`Ctrl+S` 保存),避免浏览器默认行为叠加;H1~H3 用 `Ctrl/Cmd+Alt+1/2/3`——`Ctrl/Cmd+1/2/3` 被浏览器保留为切换标签页,页面拦不住

### 5.4 草稿

* 键 `zimo-dev-tools:markdown-draft`,值为纯文本正文(与账号无关:登出不清、换账号仍可见——草稿区就地提示"草稿保存在本机浏览器,不区分账号")
* 保存:防抖 1s + `beforeunload` 同步写;写入后状态行显示"已保存 HH:MM"
* **写入异常必须捕获**:隐私模式禁用存储、或超出 localStorage 配额(约 5MB)时 `setItem` 会抛错——此时状态行提示"草稿保存失败(浏览器存储不可用或已满)",**不显示"已保存"**,控制台留一条 warn;保存失败不阻断编辑
* 读取同理包 try/catch(存储不可用时按"无草稿"处理,不抛异常打断挂载)
* "清空草稿"二次确认后删除该键并置空编辑区

### 5.5 导入导出

* 导入:隐藏 `input[type=file] accept=".md,.txt,.markdown"`;当前内容非空时先确认再覆盖
* 导出:`new Blob([src], { type: 'text/markdown;charset=utf-8' })` → `URL.createObjectURL` → 临时 `<a download>` 触发 → `revokeObjectURL`;文件名默认 `YYYY-MM-DD-untitled.md`,导出前可编辑

### 5.6 预览排版

* 独立类 `.md-body`,定义层级:标题(1~6)/段落/粗斜删除线/行内代码/围栏代码块/引用/列表/任务列表/链接/图片/表格/分割线
* 全部使用 base.css 令牌变量,亮/暗主题自动适配;代码块预置等宽字体与浅底,不做语法高亮(一期)
* 表格加边框与斑马纹;链接沿用令牌色带下划线;图片 `max-width:100%`

### 5.7 统计(状态行)

* 口径按需求 §4.5 实现,落在 `stats.js`:**单遍扫描、零分配**(一次 `for` 循环同时得出三个值)。不用 `Array.from` + `/g` 正则 —— 后者会为每个命中分配字符串(5MB 中文约 260 万个)再分配等长数组,实测慢 3~20 倍(5MB 中文 388ms → 19ms);已用 33 个边界用例 + 2 万例随机模糊校验与旧实现逐字段一致(含 `\r\n` 算一个换行、但两个字符都计入字符数)
* `chars` 按 **Unicode 码点**计(代理对算 1,组合 emoji(ZWJ 序列、带变体选择符)会拆成多个码点,这是明确口径而非缺陷);`lines` = 空内容为 0,否则按换行符切分;`words` = 中日韩汉字/假名/谚文逐字计 1,再加 `[A-Za-z0-9]+` 的匹配串数,其余字符不计
* 统计跟随 `statsSrc`:≤10 万字符即时更新;更大时按 300ms 节流(渲染侧进入暂停态后统计仍保持更新)

## 8. 决策记录

| # | 问题 | 结论 | 依据 |
| --- | --- | --- | --- |
| 1 | Markdown 渲染 | marked + DOMPurify | 成熟库、零后端、vite 好打包;自研渲染器语法覆盖不全且 XSS 面更难收 |
| 2 | 默认授权 | 仅 developer(type=0 + `{"developer"}`) | 与 serverAudioStream 同姿态;工具属开发向 |
| 3 | index / sort | 4 / 7 | 正数区顺序:home 1 → filehub 2 → serverAudioStream 3 → devTools 4 |
| 4 | 代码块高亮 | 一期不做,预留 marked extension 位 | 避免拖入高亮库膨胀产物;后续按需启用 |
| 5 | 草稿保留 | localStorage 永久保留 + 手动清空 | 与账号解耦、零清理成本,符合"纯本地"定位 |
| 6 | JSON 大文件 | >2MB 提示不阻断 | 标准 JSON API 单线程可处理,先不引入 Worker |
| 7 | 页面鉴权 | 服务端 `check` 接口把关(200/401/403) | 与文件中心/音频模块鉴权姿态一致;纯前端工具也不能"免鉴权直进" |
| 8 | 侧边栏名称 | "小工具" | 用户确认 |
| 9 | JSON 输入持久化 | **不持久化**(仅 keep-alive 保持现场) | 刷新不承诺保留(需求 §6/§8);避免"承诺恢复却未实现";与 Markdown 草稿区分 |
| 10 | 权限复检时机 | 首次挂载 + 每次 `onActivated` 静默复检 | 落实需求 §2.2 的"进入"口径;切回复检即可收敛权限撤销,成本为一次轻请求 |
| 11 | 源文 HTML 处理 | 渲染器层转义为文本,不渲染;DOMPurify 兜底 | 需求 §4.2/§7;marked 默认直通 HTML,不改会与需求冲突 |
| 12 | 软/硬换行 | `breaks: false`(只认硬换行) | 需求 §4.2 列的是"硬换行";`breaks: true` 会把软换行也变 `<br>` |
| 13 | 链接 / 图片 | 链接 `target=_blank` + `rel=noopener noreferrer`;图片允许渲染并补 `referrerpolicy=no-referrer`、`loading=lazy` | 外链同标签页会丢掉门户现场;图片不携带来源页地址,呼应需求 §7 的隐私姿态 |
| 14 | 错误原因文案 | 常见错误中文映射,未命中展示引擎原文 | 需求 §3.1#4;各引擎消息格式不同,不做臆造翻译 |
| 15 | 错误定位解析 | `(line L column C)` 优先 → `at position N` 换算 → 都无则只展示原文 | Chrome/Firefox/Safari 消息格式不一致 |
| 16 | 字数统计口径 | 见 §5.7(码点计字符、CJK 按字、拉丁数字串按词) | 需求 §4.1#8 未给口径,补齐以免验收分歧 |
| 17 | 权限点 `module` 字段 | `portal` | 与 `home`/`filehub` 一致;该字段仅分组展示,不影响侧边栏过滤与鉴权 |
| 18 | 响应式与可访问性 | 窄屏分栏降级为单栏;工具条按钮可键盘操作 | 需求 §8 主题/窄屏验收;避免移动端不可用 |
| 19 | H1~H3 快捷键 | `Ctrl/Cmd + Alt + 1/2/3` | `Ctrl/Cmd+1/2/3` 被浏览器保留为切换标签页,页面无法拦截 |
| 20 | 字符数口径 | 按 Unicode 码点计(代理对算 1,组合 emoji 拆成多个码点) | 与 `Array.from` 实现一致,不引入 `Intl.Segmenter` 依赖;口径写入需求 §4.5 |
| 21 | 复检实现 | `onMounted` + `onActivated`,用标志跳过首次激活 | keep-alive 下首次挂载也会触发 `onActivated`,不加标志会重复请求 |
| 22 | 滚动联动 | 单向(预览→编辑),按可滚动高度映射 | 需求 §4.4;编辑区滚动不反向驱动,避免互跳与抢滚动 |
| 23 | JSON 大文件重算 | >200 万字符关闭自动重算,改按钮触发 | 与需求 §3.1#8"不阻断处理"契合;避免每次停顿全量 `parse+stringify` 卡输入 |
| 24 | 草稿写入异常 | try/catch,失败提示"保存失败"且不显示"已保存" | 隐私模式/超配额下 `setItem` 会抛错,静默失败会误导用户 |
| 25 | 首次鉴权失败 | 错误态 + 重试按钮,不等同于无权限 | 网络异常不应被误判为无权限,也不能留空白页 |
| 26 | 挂载前本地判定 | 只作否定快速路径,正向等 check 200 | 避免"旧权限快照先挂载、check 回来再卸载"的闪动 |
| 27 | 拖入文件 | 直接取 `dataTransfer.files[0]`,不走目录递归 | JSON 工具只需单文件;`drop-entries.js` 是文件中心的多文件语义 |
| 28 | 大文件阈值口径 | 一律按**字符数**判(JSON 200 万字符;Markdown 10 万 / 26 万字符) | 与解析、统计成本同口径;按字节判会让中文文档晚约 3 倍触发,且每次按键全量 `TextEncoder.encode` 拷贝要 1~18ms |
| 29 | 空闲渲染 | `requestIdleCallback(fn, { timeout: 500 })` | 无 timeout 时页面持续繁忙会让回调被无限推迟(预览像卡住);rIC 只能挪动卡顿时刻 |
| 30 | 超大文档预览 | >26 万字符暂停自动预览 + 「刷新预览」手动触发 | 实测 1MB 渲染 3.5s(DOMPurify + 注入占 83%~92%),rIC 掩盖不了;与 JSON 工具 >200 万字符暂停自动重算同姿态 |
| 31 | 统计实现 | 单遍扫描、零分配;大文档按 300ms 节流 | 正则版实测慢 3~20 倍(5MB 中文 388ms/次),而它每次按键都会重算 |
